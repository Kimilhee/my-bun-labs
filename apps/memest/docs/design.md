# memest — 성경 암송 복습 게임 설계서

> 2026-07-13 grill-me 세션에서 합의된 설계. 구현 중 바뀌는 결정은 이 문서에 반영한다.

## 1. 문제 정의

사용자는 수백 개의 성경 구절을 이미 암송했다. 문제는 본문 망각이 아니라 **인출 단서의 단절**이다:

- `장절 → 말씀 첫 구절` 연결이 절반가량 끊어져 있다.
- 첫 어절만 떠오르면 나머지 본문은 이어서 암송된다.
- 기존 암송카드 방식(처음부터 자유 회상)은 "모르겠다"의 반복이라 지속 불가능.

**목표**: 장절을 보면 첫머리가 자연스럽게 떠오르는 연결을 부담 없이, 게임처럼 회복한다.
**핵심 원칙**: 실패 상태를 구조적으로 제거한다. "틀렸다"가 아니라 "힌트를 더 썼다"만 존재한다.

## 2. 범위

- **복습 전용.** 신규 암송 학습 흐름은 범위 밖 (처음 암기와 복습은 완전히 다른 처리).
- BTT(AutoHotkey 타자연습 프로그램) 포팅은 범위 밖. BTT는 데이터 원천으로만 사용.
- 사용자 1명, 스마트폰 브라우저. 백엔드 없음.

## 3. 데이터

### 원천과 변환

- 원천: `BTT/data/card*.txt` (EUC-KR, 탭 구분, `@&` = 필드 내 줄바꿈). BTT의 AHK 파서와 동일 규칙으로 해석 (DEP는 말씀 필드에 탭이 섞여 3·4열 병합).
- 변환기: `scripts/convert-btt.ts` (`bun run scripts/convert-btt.ts`)
- 산출: `data/raw-utf8/` (UTF-8 변환 원본), `data/verses.json` (카드 495개), `data/parts.json` (파트 카탈로그 16개)

### 카드 스키마

```ts
{ id, part, midTitle, title, ref, text, textEn, note, order, starred }
```

- 카드 유일 단위 = (파트, 제목, 장절). **장절이 같아도 파트가 다르면 별개 카드** (제목이 다르고 제목까지 암송 대상).
- `starred`: 원본의 `*` 표시 (옛날에 잘 안 외워졌던 카드, 87개)의 **초기값**. 앱에서 정답 화면의 장절을 더블탭하면 켜고 끌 수 있고, 그 값은 `AppData.stars`(verseId → boolean)에 남아 원본 값을 덮어쓴다. 집중 복습 필터와 리스트의 별표 필터가 이 값을 본다.
- `note`: 원본 `@&` 뒤에 붙어 있던 부가 메모 보존.

### 파트 구조 (16개)

| 파트 | 수 | 계층 |
|---|---|---|
| 5확신 / 8생활지침 | 5 / 8 | 소제목만 |
| 60구절 | 60 | 중제목 A~E × 12 |
| 시리즈 1~5 | 36×5 | 파트 대제목 + 중제목 3개(각 12) + 소제목 |
| DEP 1~8 | 242 | 대제목(파트) + 중제목 + 소제목. 구절 수 불규칙 |

- 시리즈 대제목: 하나님을 알아감 / 사랑 안에서 자라감 / 믿음 안에서 자라감 / 승리 안에서 행함 / 그리스도를 증거함
- DEP 대제목: 구원의 확신 / 경건의 시간 / 말씀 / 기도 / 교제 / 증거 / 그리스도의 주재권 / 세계비전 (18/26/37/32/30/55/26/18개)
- DEP 1은 카테고리가 대제목 자체, DEP 8(세계비전)은 중제목 없음.
- 13·60·180은 소제목만 암송, **DEP는 중제목+소제목까지 암송** (대제목은 단서로 제시됨).
- 문제 화면의 단서는 항상 `파트 + 장절` 조합 (예: `[DEP 4. 기도] 요 15:7`).

## 4. 학습 모델 — 인출 사다리

카드마다 독립적으로 사다리를 오른다. 아래로 갈수록 인출 노력이 크다.

| 단계 | 제시 | 인출 |
|---|---|---|
| A 노출 | 장절+제목+첫머리를 그냥 보여줌 (읽기만) | 없음 (프라이밍) |
| B 인식 | 짝짓기(장절↔첫구절 4쌍) / 4지선다 | 인식 |
| C 제목 회상 | 장절 + 제목 | 첫 구절 회상 |
| D 완전 회상 | 장절만 | 제목(DEP는 중제목까지)+첫 구절 회상 |

- D가 실제 암송과 동일한 조건 = 목표 상태. "제목 힌트 유무"가 C/D를 가르는 승급 축.
- **1차 구현은 C/D만.** A/B는 2차 (연결이 심하게 끊긴 카드의 재활 코스).

### 힌트 겹 (한 카드 안에서, 못 떠올릴수록 벗겨짐)

```text
단서 = 파트 배지 + 장절 + 좌상단(대제목·중제목 상시)
[힌트] 탭마다: 소제목 → 초성 → 첫머리(2~3어절) → 마지막은 정답 공개
```

- 소제목은 단서에 노출하지 않는다 — 항상 힌트 1겹 (ADR-17). C/D 레벨은 표시 차이 없이 스케줄링 승급 추적에만 남음.
- 복습 시 항상 맨몸(단서만)부터 다시 시작. 힌트 겹은 제시용이 아니라 **측정용**.
- **힌트 사용량 = 그 회차의 채점 점수.** 유일한 자가신고는 [떠올랐다] 탭과, 정답 확인 후 [잘못 떠올림] 자진 신고뿐.

### 어절 열기 (더블탭)

음성인식(STT) 채점은 정확도 문제로 전면 제거됨 (경위: ADR-14 → ADR-15). 남은 보조 장치:

- 문제 화면(단서 영역)을 **두 번 터치하면 본문이 앞에서부터 한 어절씩 열린다** (열린 수 `N/M` 표시). 카드가 바뀌면 초기화.
- 사용자는 소리 내어(또는 속으로) 스스로 암송하다가 막히면 두 번 터치로 다음 어절을 확인하고, [말씀 확인]으로 전문을 본 뒤 자가 판정한다 ([다시하기] / [잘못 떠올림] / [다음]).
- 열어본 어절 수는 세션 상태(`session.revealedWords`)라 하드드릴 점수에 반영된다 — **어절 하나마다 −3점** (`docs/hard-drill.md` §2). 힌트와 같은 이유로 공짜가 아니다.

### 첫머리 음성 확인 (ADR-16)

- [🎤 첫머리 암송] — **누르고 있는 동안만 녹음**(push-to-talk), 떼면 즉시 평가 (말 없이 떼면 조용히 복귀). 첫머리(공백 제외 10글자가 걸치는 어절까지)가 **글자 단위 LCS 50%** 이상일 때 통과. 누른 채로 맞으면 그 순간 자동 종료.
- 통과: "삥뽕"+⭕ 잠깐 → **전체 말씀 화면** ([다시하기]/[잘못 떠올림]/[다음] — 자동으로 다음 카드로 넘어가지 않음).
- 불통과: 일치율 표시 후 문제 화면 유지(재시도 가능).
- 힌트 3겹째 "첫머리"는 기본 2어절, 두 어절이 공백 제외 5자 이내면 3어절.

## 5. 스케줄링 — 없다 (진도 순회가 대신한다)

Leitner 박스·due·C/D 승급은 **v0.3.1에서 전부 제거**했다 (ADR-20). 무엇을 언제 볼지는 매일 복습의 42일 순회가 정하고, 약한 구절을 잡는 일은 하드 드릴의 부채가 맡는다. 두 축이면 충분해서 세 번째 축(due 날짜)은 유지 비용만 남았다.

남은 진행 기록은 두 가지뿐이다.

- `seen: Record<verseId, 날짜>` — "다뤄본 구절인가"만 본다. 리스트에서 장절을 탭할 때 전문부터 열지(브라우징) 단서부터 열지(암송)를 가른다.
- `stats: Record<verseId, {wrong, hints}>` — 누적 틀린 횟수·힌트 수 (모드 무관). 정답 화면의 `⊗ 3` 표시가 이 값이다.

되살릴 일이 생기면 `scheduler.ts`를 git에서 꺼내 `grade()`를 `next` 케이스에 다시 물리면 된다. 대가는 콜드 스타트(그때부터 다시 진단 배치).

## 6. 두 모드

**매일 복습**과 **하드 드릴**은 완전히 별개의 세션이다 (`AppData.sessions.daily` / `.drill`). 오가도 각자의 큐·진행이 그대로 남고, 지금 어느 모드인지는 `settings.mode`에 저장되어 앱을 다시 열어도 유지된다. 전환은 홈 화면의 두 카드 또는 설정의 모드 버튼.

### 매일 복습 (daily) — 진도 순회

- 진도표는 `lib/curriculum.ts`가 목차에서 **고정 생성**한다. 단위는 중제목(없으면 파트 전체), 목표 **12구절**에 맞춰 짧은 단위는 이어 붙이고(상한 **16**) 16을 넘는 단위는 균등 분할 → **42일 / 495구절**, 하루 8~16구절.
  - 예: 1일차 `5확신 + 8생활지침`(13) · `60구절 › A`(12) · `DEP 6 › 3+4`(16) · `DEP 6 › 5. 다리예화 (1/3)`(9).
- 진도는 **cursor(몇 번째)가 아니라 `daily.order` = 이번 바퀴에 남은 묶음 큐**다. `order[0]`이 오늘 분량이고, 다 열면 큐에서 빠지고 `daily.doneDate`에 오늘 날짜가 찍혀 그날은 끝 — 더 하고 싶으면 하드 드릴로 간다. 안 하면 큐는 그대로 멈춰 있다.
- 큐가 비면 새 바퀴를 순서 설정대로 다시 채운다 (42일차 다음은 1일차).
- **순서 설정**(`settings.dailyOrder` — 순서대로 / 거꾸로 / 랜덤)은 묶음 차례와 하루치 안의 구절 차례에 함께 적용된다. 도중에 바꿔도 **남은 큐만 다시 줄 세우므로** 빠지거나 겹치는 구절이 없다 (정순·역순은 인덱스 정렬이라 섞인 상태에서 바꿔도 제자리를 찾는다). 진행 중인 오늘 분량은 건드리지 않고 다음 묶음부터 적용.
- **점수를 매기지 않는다.** 틀린 구절만 큐 맨 뒤로 보내 맞출 때까지 — 한 번이라도 맞추면 통과.

### 하드 드릴 (drill) — 부채 점수 (ADR-18)

- 홈에서 **범위를 직접 골라** 시작한다 (파트/중제목 + 별표만 필터). 범위 선택은 이 모드에만 있다.
- 카드마다 0에서 시작하는 점수를 두고, **0 미만인 동안 세션 안에서 계속 재등장**한다.

| | 힌트 0 | 힌트 1 | 힌트 2 | 힌트 3 |
|---|---|---|---|---|
| **정답** | **+10** | −1 | −3 | −7 |
| **오답** | **−10** | −12 | −12 | −12 |

- 더블탭으로 연 어절마다 추가 −3.
- 하한 −24, 졸업 `score >= 0`. 부채를 갚는 길은 무결점 정답(+10)뿐이다.
- **재등장 위치는 부채에 반비례**: −20 이하 = 1장 뒤 / −10대 = 3장 뒤 / 한 자리 = 8장 뒤. 부채가 줄면 간격이 자동으로 벌어져 expanding retrieval이 된다.
- 재등장 상한 없음. 남은 부채는 localStorage에 지속되어 다음 드릴로 이월되고, 큐를 만들 때 부채가 깊은 카드를 앞에 세운다.
- 브라우징 회차(`peeked`)는 채점·점수·통계에서 전부 제외.
- 저장: `AppData.drill`(부채, 갚으면 항목 삭제) / `AppData.stats`(모드 무관 누적 틀린 횟수·힌트 수). 점수 로직은 `lib/drill.ts`.

### 종료 화면

"회복" 프레이밍: 오늘 연결 N개 회복 / M개 강화. 점수·정답률·스트릭 없음.

## 7. UI — 화면은 하나, 나머지는 시트

탭바·네비게이션 없음. 앱을 열면 **지금 모드의 진행 중이던 세션 카드가 그대로 복원**된다. 그 모드에 세션이 없거나 [홈으로]로 나오면 홈 화면(모드 카드 2장: 오늘 진도 / 하드 드릴 범위 고르기).

```text
┌─────────────────────────┐
│ [DEP 4. 기도]  12/20  ⚙ │  파트 배지 · 진행 · 설정(풀스크린 시트)
│       요 15: 7          │  단서 (C단계면 제목 포함)
│   (힌트 겹이 여기 쌓임)   │
│─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│ ≡ 지나온 구절            │  바텀시트 핸들
│ [ 힌트 ]   [ 떠올랐다 ]  │  엄지 존 큰 버튼 2개
└─────────────────────────┘
```

- [떠올랐다] → 정답 공개(제목 계층+말씀 전문) → [다음]. 오회상은 [잘못 떠올림] 보조 버튼으로 자진 신고.
- **좌우 스와이프 = 복습 구절 리스트 순서 브라우징**: ← 리스트의 다음 구절 / → 이전 구절 (세션 큐 순서가 아님). 이미 복습한 구절은 전문이 열린 채로, 아니면 단서부터. 브라우징으로 열린 회차는 채점 제외(`peeked`). 카드가 손가락을 따라오고(translate3d, GPU 합성) 임계값(60px)을 넘기면 슬라이드 아웃 → 새 카드가 반대편에서 슬라이드 인, 못 넘기면 스냅백. 리스트 끝은 1/3 저항.
- **바텀시트 = 이전 구절 확인** ("직전 구절 뭐였지?" 용례): 반 올리면 최근 지나온 카드, 끝까지 올리면 범위 전체 리스트(파트 헤더 포함).
- 리스트 행: **장절 탭 = 그 구절을 현재 카드로 선택** (이미 복습한 구절이면 전문이 열린 정답 화면으로 — 이 회차는 채점 제외(`peeked`), 아니면 단서부터). 나머지 영역 탭 = 미리보기 펼침, ⟲ = 단서부터 다시 암송. 대기 중이던 카드를 고르면 큐 복제 없이 맨 앞으로 이동. 별표된 구절은 장절 옆에 아주 작은 ★.
- 리스트 헤드의 **[★] 토글 = 별표한 구절만 보기** (일련번호는 범위 안 원래 위치를 유지), [반만/전체]는 시트 높이.
- **제목(대·중제목) 범위 리스트**는 암송 확인용이라 **본문 첫머리를 감추고 제목만** 보여준다 (행을 탭하면 펼쳐짐). "지나온 구절" 리스트만 첫머리를 함께 보여준다 — 찾아보는 용도라서.
- 제목 범위 리스트의 좌우 스와이프 = 이전/다음 대제목. 세션 카드와 같은 방식으로 목록이 손가락을 따라오고 임계값을 넘기면 슬라이드 아웃 → 새 목록이 반대편에서 슬라이드 인.
- **전부 공개**: 모든 구절이 `장절+제목+첫머리`(탭하면 전문). 이미 다뤄본 구절만 ⟲(다시 암송)이 붙고, 장절 탭 시 전문부터 열린다(미확인 구절은 단서부터).
- 정답 화면 **본문 밑 오른쪽**에 회색으로 작게 기호만: `⊗ 3 · ⊖ 12 · ⟳ 2` — ⊗ 총 틀린 횟수(`stats.wrong`, 모드 무관 누적) · ⊖ 남은 하드드릴 부채 · ⟳ 졸업까지 필요한 무결점 횟수(`ceil(부채/10)`). 부채는 하드드릴이 켜져 있을 때만 쌓이므로 ⊖·⟳도 그때만 뜬다. 상단 진행 배지에서는 뺐다.
- 하드드릴 범위 시트(홈에서만): 파트 체크박스 + ▶ 탭으로 중제목 펼침 + "별표한 구절만". `Settings.scopeParts` 항목은 `코드`(파트 전체) 또는 `코드#중제목`이고, `inScope`가 둘 다 해석한다 — 예전에 저장된 순수 코드 값이 그대로 동작한다.
- 세션 화면의 파트 배지 = 그 파트의 구절 리스트 (범위 변경은 홈에서만).
- 설정 시트: 모드 선택(매일 복습 | 하드 드릴), 매일 복습 순서(순서대로 | 거꾸로 | 랜덤), 홈으로, 데이터 내보내기/가져오기(JSON), 진행도 초기화.
- 레이아웃 고정: 하단 존(버튼+핸들)이 화면의 **20%를 고정 점유** → 버튼 줄은 항상 80% 지점에서 시작, 버튼 높이도 고정(라벨이 바뀌어도 흔들림 없음). `#root`까지 height:100% 체인 필수. 대제목·중제목은 단서 영역 **좌측 상단 모서리**에 작게 상시 표시 (소제목은 힌트 — ADR-17).

## 8. 기술

- 모노레포 디폴트: React 19 + Vite + TS strict + Biome, `bun` 런타임. 백엔드 없음.
- 저장: localStorage (`memest:v1` — seen·stats·drill·stars·설정·진도 큐·모드별 세션). 백업은 JSON 내보내기/가져오기. 스키마가 바뀌면 `storage.ts`가 기본값 병합과 마이그레이션으로 흡수한다.
- 사용: 배포 주소(https://kimilhee.github.io/my-bun-labs/)가 기본. 개발 중엔 `bun dev`(`--host`) → 폰이 같은 Wi-Fi로 접속.
- shadcn/ui 미도입 (프로토타입 단계, 화면 3개에 과함 — 필요해지면 도입).
