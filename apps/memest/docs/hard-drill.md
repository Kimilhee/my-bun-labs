# 하드드릴 모드

> **상태: 구현됨 (v0.2.9). v0.3.0부터 설정 토글이 아니라 두 모드 중 하나다** — 결정 요약은 `ADR.md`의 ADR-18·ADR-19, 동작은 `design.md` §6. 이 문서는 점수 규칙의 상세와 그렇게 정한 이유를 담는다.
> 구현: `src/lib/drill.ts`(점수·간격) + `app-state.ts`의 `next` 케이스.

## 1. 목적

> "틀린 건 맞출 때까지 계속 나온다. 힌트 쓰고 맞춘 것도 다시 나온다. **완벽하게 한 번에** 맞춰야 안 나온다."

애매하게 맞춘 구절을 "암송했다"로 치지 않는 모드. 카드마다 **부채(debt) 점수**를 매기고, 부채가 남아 있는 동안 세션 안에서 계속 재등장시킨다. 부채는 무결점 정답(힌트 0 + 정답)으로만 갚을 수 있다.

기존 Leitner 스케줄링(`scheduler.ts`)과는 **완전히 독립**이다. 하드드릴 점수는 일상 복습의 재등장 빈도(`box`/`due`)에 영향을 주지 않고, 그 반대도 아니다.

## 2. 점수 규칙

카드별 점수는 **0에서 시작**하고, 매 회차마다 아래 값을 더한다.

| | 힌트 0 | 힌트 1 | 힌트 2 | 힌트 3 |
|---|---|---|---|---|
| **정답** | **+10** | −1 | −3 | −7 |
| **오답** | **−10** | −12 | −12 | −12 |

- 힌트 감점은 누적이다: 1겹 −1, 2겹 −2, 3겹 −4 → 3겹 다 쓰면 −7.
- **더블탭으로 연 어절 하나마다 −3.** 회차 점수에 그대로 더해진다 (오답이어도 합산한다 — 힌트와 달리 어절 열기는 "정답을 조금씩 보는 것"이라 회차 결과와 무관하게 값이 매겨져야 한다). 무결점 정답 +10이므로 어절 3개까지는 그래도 부채가 줄고, 4개부터는 순부채가 된다.
- **오답이면 힌트 감점을 합산하지 않고 그 회차 점수를 −10/−12로 확정한다.** (근거는 §6)
- 힌트를 쓰고 맞춰도 가산점은 없다. 순감점만 있다.
- 이 앱의 힌트는 3겹이 전부다 (`hints.ts:hintLayers` — 소제목 / 초성 / 첫머리). 3겹 다음은 정답 공개이고, 정답 공개는 오답으로 친다 (현행 `app-state.ts`의 `wrong = s.revealed || action.wrong`과 동일).

### 졸업 · 하한

- **졸업: `score >= 0`.** 점수가 0 이상이 되면 그 세션에서 더 이상 재등장하지 않는다.
- **하한: −24.** 아무리 깎여도 이 밑으로는 안 내려간다. 최악의 경우에도 무결점 3회면 졸업할 수 있다는 보장이 된다.
- 하한 −24는 **잠정값**이다. 써보고 이상하면 조정한다.

### 부채 → 필요한 무결점 반복 횟수

`ceil(부채 / 10)` 이다.

| 회차 결과 | 점수 | 졸업까지 필요한 무결점 정답 |
|---|---|---|
| 힌트 쓰고 정답 (−1 ~ −7) | −1 ~ −7 | **1회** |
| 힌트 없이 오답 | −10 | **1회** |
| 힌트 쓰고 오답 | −12 | **2회** |
| 무너진 회차 2번 | −22 ~ −24 | **3회** |
| 하한 바닥 | −24 | **3회** (최대) |

부채는 선형으로 쌓이고, 무너진 회차 하나가 약 1.2회의 무결점 반복을 요구한다. 폭발하지 않는다.

`−10 + 10 = 0`이므로 **힌트 없이 한 번 틀린 카드는 무결점 1회로 졸업한다.** 이건 의도된 것이다 — 힌트를 안 쓰고 시도했다는 건 완전히 모르는 게 아니라 헷갈린 것에 가깝다. "틀렸으면 무조건 2회"를 원하면 −11로 내리면 되지만, 그러면 −12와 실질 차이가 없어져 −10으로 낮춘 의미가 사라진다.

## 3. 재등장 위치 — 부채 깊이에 반비례

무조건 큐 맨 뒤로 보내면 안 된다. 36구절 세션에서 첫 카드가 35장 뒤에 나오면 재학습이 아니라 초면이다. **부채가 깊을수록 짧은 간격으로** 다시 넣는다.

| 점수 | 재삽입 위치 | 의미 |
|---|---|---|
| −24 ~ −20 | **1장 뒤** | 완전히 안 외워짐 — 바로 다시 |
| −19 ~ −10 | **3장 뒤** | 크게 무너짐 |
| −9 ~ −1 | **8장 뒤** | 살짝 흔들림 |

삽입 인덱스는 `Math.min(gap, 남은 큐 길이)`. 큐가 짧으면 자동으로 맨 뒤가 되므로 별도 분기가 필요 없다.

- **간격 0은 금지, 최소 1.** 방금 정답을 본 직후 바로 다시 보는 건 인출이 아니라 작업기억에서 그대로 읽는 것이라 학습 효과가 거의 없다. 한 장만 건너뛰어도 그 사이 카드가 작업기억을 밀어낸다.
- **부수 효과가 좋다**: 카드가 나아질수록 부채가 줄고(−24 → −14 → −4) 간격이 자동으로 1 → 3 → 8로 벌어진다. 학습과학의 **expanding retrieval**(간격을 점점 늘리며 인출) 곡선이 튜닝 파라미터 없이 그대로 나온다.

### 재등장 상한은 두지 않는다

한때 "카드별 세션 내 재등장 상한 4회"를 넣으려 했으나 **하한 −24와 모순이라 폐기**했다. −24를 갚으려면 무결점 3회가 필요한데, −24까지 쌓는 데 이미 등장 2회를 쓴다. 상한이 4회면 남은 기회 2회로 +20밖에 못 갚아서, **마지막에 두 번 연속 완벽하게 맞췄는데도 부채를 진 채 퇴출**된다. 하드드릴이 존재하는 이유인 바로 그 카드가 세션 안에서 절대 졸업 못 하는 구조가 된다.

상한 없이 **졸업할 때까지 계속** 등장시킨다. 세션 말미에 남은 카드가 적어 방금 본 구절이 곧바로 다시 나오는 것도 허용한다 — 그렇게라도 반복해야 제거되는 카드가 실제로 있다. 그만두고 싶으면 설정 → "진행 중인 세션 종료"로 나가면 되고, 부채는 localStorage에 남아 다음 세션으로 이월된다.

### 부채의 이월

- 점수는 localStorage에 지속된다. 세션을 다시 열어도 빚은 그대로다 (재시작이 리셋 치트가 되면 안 된다).
- **매일 복습에는 부채 카드를 섞지 않는다.** 하루치는 진도표가 정하는데 부채 카드를 끼워 넣으면 그날 분량이 예고 없이 길어지고 진도가 굶는다. 부채 갚기는 범위를 직접 정하는 하드 드릴에서 한다.
- **하드 드릴 큐는 부채가 깊은 카드를 앞에 세운다.** 범위를 직접 지정하는 모드라 길이 예측 문제가 없다.

## 4. 기존 세션 모드와의 관계 (v0.2 기준 — v0.3에서 아래처럼 정리됨)

> v0.3.0부터 "일일/집중 세션 + 하드드릴 토글"이 **매일 복습 / 하드 드릴 두 모드**로 접혔다 (ADR-19).
> 하드드릴 점수는 **하드 드릴 모드에서만** 돈다. 매일 복습은 점수를 매기지 않고, 틀린 구절만 큐 뒤로 보내 맞출 때까지 반복한다. 아래 표는 그 배경이 된 v0.2의 대비다.

~~하드드릴은 새 `SessionMode`가 아니라 일일/집중 세션 위에 얹는 설정 토글이다.~~ → v0.3.0에서 **하드 드릴이 곧 `SessionMode`**가 됐다 (ADR-19).

현행 집중 세션(ADR-5)의 재큐잉은 `wrong || hintsUsed > 0` → **큐 맨 뒤** 재삽입, "맨몸으로 열릴 때까지" 반복이다 (`app-state.ts`의 `next` 케이스). 하드드릴은 이것의 상위호환이다.

| | 현행 집중 세션 | 하드드릴 |
|---|---|---|
| 졸업 조건 | 맨몸 정답 **1회** | 부채만큼 **N회** |
| 재등장 위치 | 항상 맨 뒤 | 부채 깊이에 반비례 |
| 세션 간 이월 | 없음 (리셋) | 부채 유지 |

- v0.3.0: **하드 드릴 모드 = 점수 기반 재큐잉**, **매일 복습 = 점수 없이 틀린 것만 맨 뒤로**.

ADR-5를 폐기하지 않고 확장하는 형태다.

**Leitner 채점(`grade()`)은 두 모드 모두에서 평소대로 돈다.** 다만 v0.3.0부터 그 결과(box/due)로 카드를 고르는 화면은 없다 — 기록만 쌓는다 (ADR-20). 하드 드릴은 "지금 이 세션에서 확실히 잡는" 도구이고, 장기 반복은 매일 복습의 42일 순회가 맡는다.

### 브라우징 회차 제외

좌우 스와이프로 지나온 구절을 열어보는 회차(`session.peeked`)는 **Leitner 채점과 마찬가지로 하드드릴 점수·통계에서도 전부 제외**한다. 그러지 않으면 구경만 해도 점수가 깎이고, 더 나쁘게는 **정답을 다 본 상태에서 "맞췄다"를 눌러 +10을 먹는 치트**가 된다.

## 5. 데이터 모델

```ts
// AppData에 추가
drill: Record<string, number>  // verseId → 부채 점수(음수). 갚으면 항목 삭제
stars: Record<string, boolean> // 수동 별표 (BTT 원본의 Verse.starred를 덮어씀)
stats: Record<string, { wrong: number; hints: number }>  // 누적 기록, 모드 무관
// Settings에 추가
hardDrill: boolean
```

- **부채를 갚은 카드는 `drill`에서 지운다.** 항목이 있다는 것 자체가 "빚이 남았다"는 뜻이라 조회가 단순해지고, localStorage도 안 부푼다.
- **`stats`는 매 회차마다 집계한다** (첫 회차만 세는 `counted`와 다르다). 한 세션에서 세 번 틀렸으면 3회다 — 그게 정직한 "총 틀린 횟수"다. 틀리지도, 힌트를 쓰지도 않은 회차는 아예 기록하지 않아 495개 빈 항목이 생기지 않는다.

- **`Progress`(Leitner)와 분리**한다. "하드드릴에서만 관리" 요구가 타입 수준에서 지켜진다.
- **`stats`의 틀린 횟수는 모드와 무관하게 전부 집계한다.** 정렬용 통계일 뿐 스케줄러 입력이 아니므로 "하드드릴에서만" 제약과 충돌하지 않는다. 하드드릴에서만 집계하면 "평소에 자주 틀리는 구절" 랭킹이 나오지 않아 데이터가 반쪽이 된다.
- `storage.ts`의 기본값 병합(`?? {}`)으로 하위호환 (CLAUDE.md 규칙).
- 세션 내 카드별 등장 횟수는 기존 `session.history`로 셀 수 있으므로 별도 필드가 필요 없다.

## 6. 설계 근거

### 왜 오답 시 힌트 감점을 합산하지 않나 (가장 중요한 결정)

최초 안은 감점 합산이었다: 맨몸 오답 −5, 힌트 3개 쓰고 오답 −12. 이러면 단서 화면에서 가물가물할 때 합리적 플레이가 **힌트를 안 쓰는 것**이 된다.

- 힌트 없이 바로 포기: **−5 확정**
- 힌트 3개 쓰고 도전: 맞으면 −7, 틀리면 −12 → **어느 쪽이든 −5보다 나쁨**

즉 **힌트가 가장 필요한 어려운 카드에서 힌트를 회피하는 게 이득**이 된다. 게다가 3번째 힌트 겹은 `첫머리`(첫 2~3어절)로 이 앱의 학습 목표(장절 → 첫 구절 연결)에 가장 직접적으로 기여하는 스캐폴딩인데, 그걸 피하게 만드는 건 손해다. 자가 판정이라 "그냥 틀렸다 누르기"의 비용도 0이다.

합산을 없애고 오답을 −10/−12로 확정하면:

- 힌트 쓰고 맞추기(−7)가 포기(−10)보다 항상 이득 → 힌트를 쓸 이유가 생긴다.
- 힌트를 쓰고 도전했다가 틀려도 추가 비용은 −2뿐 → 도전이 억제되지 않는다.
- "무너진 회차는 무결점 2회"라는 톱니(−12 > +10)는 그대로 남는다.

잃는 건 "힌트 쓰고도 틀렸다"는 진단 정보인데, `stats.hints`에 남으므로 손실이 아니다.

### 왜 하한이 필요한가

하한이 없으면 진짜 모르는 카드가 −12, −24, −36으로 무한히 내려가고 갚는 데 필요한 반복도 계속 늘어난다. 무결점 정답률이 대략 55%를 밑돌면 점수가 발산해서 그 카드 하나가 세션을 장악하고, 종료가 보장되지 않는다. −24는 "최악이어도 무결점 3회면 끝"이라는 상한을 준다.

### 왜 점수를 세션 한정으로 두지 않나

세션 재시작이 부채 리셋 치트가 된다. 지속시켜야 "오늘 못 끝낸 빚"이 다음 세션으로 넘어가고, 그게 §3의 세션 종료 보장과 짝을 이룬다. 시간에 따른 점수 감쇠는 지금 필요 없다 (YAGNI).

## 7. 미결 / 별개 이슈

- **하한 −24와 간격 1/3/8은 잠정값.** 실사용 후 조정.
- **틀린 횟수 정렬 UI는 아직 없다.** `stats`를 먼저 쌓아두고, 정렬 뷰(구절 리스트 시트의 정렬 옵션 등)는 데이터가 모인 다음에 붙인다.
- **수동 별표는 v0.2.16에 들어왔다.** 정답 화면의 장절 더블탭으로 켜고 끄며, `AppData.stars`가 BTT 원본의 `*` 표시(87개)를 덮어쓴다. `stats.wrong`·남은 부채 기반의 자동 표시는 여전히 없다 (데이터가 쌓인 뒤에 판단).
- ~~암송 중 시작 화면으로 나가는 경로의 발견성.~~ v0.3.0에서 설정의 [홈으로]가 세션을 유지한 채 홈으로 보내면서 해결.
- **(별개) 스와이프 브라우징이 큐 순서를 흐트러뜨린다.** `redoVerse`가 카드를 원래 자리에서 빼 맨 앞으로 옮기므로(`app-state.ts`), 부채 간격으로 꽂아둔 위치가 스와이프로 무너진다. 반복 등장 자체는 문제가 아니라고 판단해 그대로 두었다.
